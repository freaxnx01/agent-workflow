# Email style — lead with a TL;DR, then keep it short

Applies to any mail drafted for me to send, in any language.

- **Open with a `TL;DR:` block.** The first paragraph states the answer, the
  verdict, or the ask — whatever the recipient needs if they read nothing else.
  Not a topic sentence („anbei meine Analyse…"), the actual conclusion.

- **Then keep it short.** A mail is not a written-up analysis: it carries the
  conclusion and whatever the recipient has to *do*, not the derivation that got
  there. Cut the reasoning chain, the ruled-out hypotheses, and the caveats that
  change nothing for them. Aim well under a screen; if the underlying work was
  long, that length belongs in a notes file or a follow-up on request, not in
  the mail.

- **Enumerate what you need from them**, briefly, so it can be answered point by
  point — and say which points actually matter if not all do.

Detail is not deleted, it is *held back*. Offer it („Details gerne auf Anfrage")
rather than pre-emptively pasting it, and keep the long version on disk so it can
be sent if asked.

## Relation to the answer-formatting rule

The `TL;DR:` rule for chat answers (see `response-formatting.md`) kicks in past
two sentences and repeats at the end of a long answer. For mail the TL;DR is
**always** present and **never** repeated — a mail is read top to bottom in one
screen, so a closing restatement just pads it.
