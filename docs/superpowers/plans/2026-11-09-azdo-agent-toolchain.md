# Azure Pipelines Agent .NET Tool-Chain Variant Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in `dotnet` stage to the agent image, with a pinned .NET LTS SDK that is SHA-512 verified at build time, so the agent can build and test what it writes. A bare `docker build` must keep producing today's image.

**Architecture:** `docker/azp-agent/Dockerfile` becomes multi-stage:

- `base`: today's instructions, unchanged.
- `dotnet`: `FROM base`, adds the SDK and `ENV AWF_TOOLCHAIN=dotnet`.
- `default`: a bare `FROM base AS default`, last.

A hermetic Layer-1 test guards the stage layout and the pin. The guide documents the target build and the pool demand. Tasks 1–2 are implementer work in this repo. Task 3 is the orchestrator's live proof in the private sandbox.

**Tech Stack:** Docker multi-stage builds, Bash 5, awk/grep, hadolint (via pre-commit), shellcheck, Azure Pipelines demands.

**Spec:** `docs/superpowers/specs/2026-11-09-azdo-agent-toolchain-design.md`

## Global Constraints

- The repository is **public**. Write no organisation, pool, host or work-repo names; use `<org>`, `<pool>`, `<agent-host>`, `<name>`, `<volume>` and `<image>`. The sandbox repo `practice` is already named in the spec and may be named.
- The bash prelude is `set -euo pipefail` + `IFS=$'\n\t'`. Exit codes are part of the API: document them in the script header.
- Layer-1 tests are hermetic: no network and no Docker. They are discovered by `tests/run-all.sh` through the name pattern `run-*-tests.sh`.
- Stage names are exactly `base`, `dotnet` and `default`. `default` is the **last** stage and is `FROM base`.
- The SDK pin is `ARG DOTNET_SDK_VERSION` and `ARG DOTNET_SDK_SHA512`, declared in the `dotnet` stage with defaults. The SHA-512 is 128 lowercase hex characters, read from the official release metadata. **Never invent a version or a hash.**
- The SDK goes to `/usr/share/dotnet`, with `dotnet` symlinked onto the PATH. Set these ENV values:
  - `DOTNET_ROOT=/usr/share/dotnet`
  - `DOTNET_CLI_TELEMETRY_OPTOUT=1`
  - `DOTNET_NOLOGO=1`
  - `AWF_TOOLCHAIN=dotnet`
- The install runs as root; the stage ends with `USER 1000`.
- The SDK is never installed at job time: no `UseDotNet@2` and no `dotnet-install.sh`. There is no NuGet cache volume and no private feed.
- `CHANGELOG.md` is generated by git-cliff. Do not hand-edit it.

## Review Focus

1. **A reordered Dockerfile that silently changes the default image.** For example, `dotnet` placed last, or instructions added under `default`. A bare build must stay today's image. Pinned in Task 1:
   - `dockerfile_last_stage_is_default_from_base`
   - `dockerfile_default_stage_has_no_instructions`
   - the Step 6 layer comparison.
2. **A hash check that does not actually gate extraction.** For example, `sha512sum -c` placed after `tar`, or the check's exit status swallowed by `|| true` or a pipe. Pinned in Task 1 by `dockerfile_sha512_check_precedes_extract`, and live in Task 3 Step 2 (a wrong SHA fails the build).
3. **`AWF_TOOLCHAIN` set as an `ARG`, or set in `base`.** As an ARG the agent would not advertise it. In `base`, every default agent would match the demand. Pinned in Task 1 by `dockerfile_toolchain_env_only_in_dotnet`.
4. **The `dotnet` stage left running as root.** It inherits `USER 1000` from `base`, then switches to root for the install. If it never switches back, jobs run as root. Pinned in Task 1 by `dockerfile_dotnet_stage_ends_as_user_1000`.
5. **A placeholder or truncated SHA-512 left in the ARG default.** Pinned in Task 1 by `dockerfile_sha512_arg_is_128_hex`. Task 1 Step 5 also checks the hash against a fresh download before the commit.

### Task 1: Multi-stage Dockerfile with the pinned .NET SDK, plus a Layer-1 guard

**Files:**
- Modify: `docker/azp-agent/Dockerfile`
- Create: `tests/run-azp-agent-dockerfile-tests.sh`

**Interfaces:**
- Produces, for Tasks 2 and 3: the build targets `base`, `dotnet` and `default`.
  - `docker build -f docker/azp-agent/Dockerfile --target dotnet -t <image>-dotnet .` builds the variant.
  - A build with no `--target` produces `default`, which is today's image.
- Produces: the `dotnet` stage's `ENV AWF_TOOLCHAIN=dotnet`. Task 2 documents it as the demand `AWF_TOOLCHAIN -equals dotnet`.
- Produces: the chosen `DOTNET_SDK_VERSION`, which sets the SDK major. Task 3's sample must target that major's TFM (`net<major>.0`).
- Test runner: `tests/run-azp-agent-dockerfile-tests.sh`.
  - Env `DOCKERFILE` overrides the file under test. The default is `$ROOT/docker/azp-agent/Dockerfile`.
  - Exit codes: 0 when all checks pass, 1 when any assertion failed.

- [ ] **Step 1: Write the failing test.**

  Copy the harness of `tests/run-azp-agent-start-tests.sh`: the prelude, `pass`/`fail`/`assert_eq`, the colour handling and the summary/exit. Parse the Dockerfile with awk only. Strip comment lines, and join `\`-continued lines before parsing.

  Write these checks against the real file:
  - `dockerfile_has_three_named_stages`: the `FROM … AS <name>` names, in order, are `base dotnet default`.
  - `dockerfile_base_is_the_pinned_debian`: the `base` FROM is `debian:13-slim@sha256:f6b08b09a05725f9431502d3b5714f5c4576e82c1a84fa1debe0c24a7e0c3ec4 AS base`.
  - `dockerfile_last_stage_is_default_from_base`: the last FROM line is exactly `FROM base AS default`.
  - `dockerfile_default_stage_has_no_instructions`: no non-comment, non-blank line follows the last FROM.
  - `dockerfile_dotnet_stage_from_base`: the stage line is `FROM base AS dotnet`.
  - `dockerfile_sha512_arg_is_128_hex`: in the `dotnet` stage, `ARG DOTNET_SDK_SHA512=<v>` has `<v>` matching `^[0-9a-f]{128}$`.
  - `dockerfile_sdk_version_arg_set`: `ARG DOTNET_SDK_VERSION=<v>` matches `^[0-9]+\.[0-9]+\.[0-9]+$`.
  - `dockerfile_sha512_check_precedes_extract`: in the `dotnet` stage, a `sha512sum -c` occurs before the `tar` that extracts to `/usr/share/dotnet`, and both are in one RUN. The check is not followed by `|| true`.
  - `dockerfile_download_uses_version_arg`: the tarball URL contains `${DOTNET_SDK_VERSION}`, and its host is `builds.dotnet.microsoft.com`.
  - `dockerfile_toolchain_env_only_in_dotnet`: `AWF_TOOLCHAIN=dotnet` appears in an `ENV` instruction in the `dotnet` stage. It appears nowhere in `base` or `default`, and never as an `ARG`.
  - `dockerfile_dotnet_env_set`: the `dotnet` stage's ENV sets `DOTNET_ROOT=/usr/share/dotnet`, `DOTNET_CLI_TELEMETRY_OPTOUT=1` and `DOTNET_NOLOGO=1`.
  - `dockerfile_dotnet_stage_ends_as_user_1000`: the last `USER` in the `dotnet` stage is `1000`.

  Then add one negative case per guard. Each writes a mutated copy of the real Dockerfile into a `mktemp -d` dir (`trap` cleanup), runs the checks against it via `DOCKERFILE`, and asserts that they **fail**:
  - `negative_dotnet_last_is_caught`: swap the `dotnet` and `default` stages.
  - `negative_short_sha_is_caught`: shorten the SHA-512 by one character.
  - `negative_root_user_is_caught`: delete the final `USER 1000` in the `dotnet` stage.
  - `negative_toolchain_in_base_is_caught`: move `AWF_TOOLCHAIN` into `base`.

  For this to work, wrap the checks in a function that takes the Dockerfile path and returns a failure count. The negative cases assert a non-zero count without printing the inner results.

- [ ] **Step 2: Run the test to verify it fails.**

  Run: `bash tests/run-azp-agent-dockerfile-tests.sh`
  Expected: FAIL. `dockerfile_has_three_named_stages` and the stage-dependent checks fail on today's single-stage file.

- [ ] **Step 3: Look up the SDK pin from the official metadata, on the day.**

  1. Read `https://builds.dotnet.microsoft.com/dotnet/release-metadata/releases-index.json`. If that is unreachable, use the `dotnetcli.blob.core.windows.net/dotnet/release-metadata/` equivalent. Pick the **newest** `channel-version` whose `release-type` is `lts` and whose `support-phase` is `active`. Two LTS channels can be listed at once; take the newest.
  2. Take that channel's `latest-sdk`.
  3. Open `…/release-metadata/<channel>/releases.json`. Find the release whose `sdk.version` (or `sdks[].version`) equals that SDK. In its `files[]`, take the entry named `dotnet-sdk-linux-x64.tar.gz` and read its `url` and `hash`. The `hash` is the SHA-512.
  4. Download that URL into a scratch dir and run `sha512sum` on it. The result must equal `hash`. **If it differs, stop and report. Do not commit either value.**
  5. Record the version, the hash, the metadata URL and the date. They go in the Dockerfile comment and in the commit body.

- [ ] **Step 4: Restructure `docker/azp-agent/Dockerfile`.**
  - `base`: today's instructions, **byte-identical** except that ` AS base` is appended to the existing FROM line. Extend the header comment with the three targets and "bump `DOTNET_SDK_VERSION` and `DOTNET_SDK_SHA512` together".
  - `dotnet`, in this order:
    1. `FROM base AS dotnet`
    2. The two `ARG`s with the Step 3 values as defaults.
    3. `USER root`
    4. One `RUN`, which does the following in order:
       - curl the tarball (`-fsSL`) from `https://builds.dotnet.microsoft.com/dotnet/Sdk/${DOTNET_SDK_VERSION}/dotnet-sdk-${DOTNET_SDK_VERSION}-linux-x64.tar.gz`, or the exact host path that `files[].url` gave;
       - write `"${DOTNET_SDK_SHA512}  <tarball>"` to a checksum file and run `sha512sum -c <file>`. Use no pipe, which avoids hadolint DL4006;
       - `mkdir -p /usr/share/dotnet` and `tar -xzf` into it;
       - `ln -s /usr/share/dotnet/dotnet /usr/local/bin/dotnet`;
       - remove the tarball and the checksum file.
    5. `ENV` with the four values from Global Constraints.
    6. `USER 1000`
  - `default`: `FROM base AS default`, and nothing after it.
  - Add native packages only if `dotnet --info` fails in Step 6. `libicu76`, `libssl3t64` and `zlib1g` are already in `base`.

- [ ] **Step 5: Run the tests and lint.**
  - `bash tests/run-azp-agent-dockerfile-tests.sh`: all pass, the negative cases included.
  - `bash tests/run-all.sh`: exits 0, and the new runner is listed.
  - `shellcheck -x tests/run-azp-agent-dockerfile-tests.sh`: clean.
  - `pre-commit run hadolint-docker --files docker/azp-agent/Dockerfile`: clean. hadolint is not on the PATH, so this hook runs it through Docker. If it flags something new, fix it. If a fix is impossible, add an inline `# hadolint ignore=DLxxxx` with a reason.
  - `pre-commit run --files tests/run-azp-agent-dockerfile-tests.sh docker/azp-agent/Dockerfile`: clean. Run `git add` on the new test first, because pre-commit skips untracked files.

- [ ] **Step 6: Build both targets and prove that G2 holds.**

  Docker is available on the dev host. If `docker info` fails, mark this step for the orchestrator (Task 3) and continue.
  1. `git show HEAD:docker/azp-agent/Dockerfile > "$scratch/Dockerfile.before"`, then `docker build -f "$scratch/Dockerfile.before" -t azp-agent:before .`
  2. `docker build -f docker/azp-agent/Dockerfile -t azp-agent:after .` (no `--target`), with the same warm cache.
  3. Run `docker image inspect -f '{{json .RootFS.Layers}} {{json .Config.Env}} {{json .Config.Entrypoint}} {{json .Config.User}} {{json .Config.WorkingDir}}'` on both images. **Expected: identical output.**
  4. `docker build -f docker/azp-agent/Dockerfile --target dotnet -t azp-agent:dotnet .` succeeds.
  5. `docker run --rm --entrypoint bash azp-agent:dotnet -c 'id -u && dotnet --info && printenv AWF_TOOLCHAIN'` prints `1000`, the pinned SDK version, and `dotnet`.
  6. Remove the three local tags and the scratch files afterwards.
