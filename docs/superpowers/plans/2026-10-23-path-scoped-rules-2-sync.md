# Path-scoped rules (2/4) — sync-ai-instructions fan-out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Teach the `sync-ai-instructions` skill to install `.ai/rules/` from ai-instructions as `.claude/rules/`, `.github/instructions/` and an `opencode.json` `instructions` entry.

**Architecture:** The skill is LLM-executed Markdown, so there is no unit harness. The change is new instructions in `SKILL.md` (fetch list, a new step, report line), proven by a de-risking spike before the edit and an acceptance run against `agent-workflow` after it.

**Tech Stack:** `SKILL.md` prose, `gh api`/`curl`, `jq` for the `opencode.json` merge.

**Spec:** `freaxnx01/agent-workflow` → `docs/superpowers/specs/2026-10-23-path-scoped-rules-design.md`

**Repo:** `freaxnx01/agent-skills` (marketplace `freax-agent-skills`), plugin `plugins/sync-ai-instructions/`.

**Depends on:** plan 1 merged (`.ai/rules/` exists upstream).

## Global Constraints

- Generated-file marker, first line after frontmatter: `<!-- generated by sync-ai-instructions from ai-instructions/.ai/rules/<folder>/<name>.md — do not edit, re-run /sync-ai-instructions -->`
- `.claude/rules/<name>.md` frontmatter: `paths:` as a YAML list of the source `globs`.
- `.github/instructions/<name>.instructions.md` frontmatter: `applyTo: "<globs joined by ,>"` (no spaces).
- `opencode.json`: ensure `instructions` contains the literal entry `.claude/rules/*.md`; create `{"$schema": "https://opencode.ai/config.json", "instructions": [".claude/rules/*.md"]}` when absent; never reorder or drop other keys or entries.
- Installed set = `.ai/rules/base/*` + `.ai/rules/<chosen stack>/*`; nothing else.
- Stale cleanup deletes only files carrying the marker; unmarked files are never touched.
- Existing generated file with different content → show the diff before overwriting (the skill's existing rule for `CLAUDE.md`).
- Skill keeps its closing self-improvement line.
- `SKILL.md` (OpenClaw) has no rules mechanism: sync appends every installed rule body, in name order, after the assembled content under a `## Path-scoped rules` heading, each preceded by `### <name> (applies to <globs>)`. Regenerated whole on every run, so no duplicate on re-run.
- Version: `plugin.json` `0.4.0` → `0.5.0`; `CHANGELOG.md` gets `## [0.5.0]`.

## Review Focus

- A stack with **no** rules folder upstream (every stack except `ci` after plan 1) — and an upstream with no `.ai/rules/` at all — the step must install what exists and treat each 404 as "no rules", not an error.
- An existing `opencode.json` with comments or trailing commas (JSONC) — `jq` fails; the skill must stop and ask instead of overwriting the file.
- A repo that already has a hand-written `.claude/rules/local.md` — survives every run.
- Second run on an unchanged upstream — empty `git status`.
- A rule removed upstream — its two generated files disappear; `opencode.json` stays (the glob still covers the rest).
