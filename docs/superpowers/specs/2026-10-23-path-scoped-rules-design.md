# Path-scoped rules for consumer repos — design

**Date:** 2026-10-23
**Status:** draft, awaiting review
**Repos touched:** `freaxnx01/ai-instructions`, `freaxnx01/agent-skills` (marketplace `freax-agent-skills`, plugin `sync-ai-instructions`), `freaxnx01/agent-workflow`

## Problem

Every consumer repo carries one assembled `CLAUDE.md` (base instructions + one stack
overlay, 26–38 KB, roughly 7–10k tokens), and every line of it loads into every
session — the Bash conventions while editing C#, the GitHub Actions rules while
writing docs.

Claude Code's `.claude/rules/` offers a middle tier between "always loaded"
(`CLAUDE.md`) and "read on demand" (the `.ai/references/**` links ai-instructions
already uses): a rule with `paths:` frontmatter loads only when Claude works with a
matching file ([docs](https://code.claude.com/docs/en/memory.md#organize-rules-with-claude-rules)).

The catch is that the pipeline does not only run Claude:

| Agent | Path-scoped instructions? | Source |
|---|---|---|
| Claude Code | `.claude/rules/*.md`, `paths:` frontmatter | memory docs |
| GitHub Copilot | `.github/instructions/*.instructions.md`, `applyTo:` | Copilot docs |
| OpenClaw (`SKILL.md`) | none — a single assembled file | sync |
| opencode | **none** — reads `AGENTS.md` (falls back to `CLAUDE.md`) plus the `instructions` array in `opencode.json`, always loaded; `.claude/rules/` is not read | [opencode rules](https://opencode.ai/docs/rules/) |

Moving a section out of `CLAUDE.md` into `.claude/rules/` alone would silently strip it
from every opencode run — the glm fleet default for product repos.

## Goal and success criteria

- A section that only matters for some files is authored **once** in ai-instructions
  and reaches Claude, Copilot and opencode.
- Claude and Copilot load it only for matching files; opencode loads it always
  (no token win for opencode, but **no loss**).
- `/integration` detects a repo where rules exist but opencode cannot see them.
- Pilot on the `ci` stack (agent-workflow itself): Bash conventions (~1.3 KB),
  GitHub Actions conventions (~2.0 KB) and PowerShell 5.1 (~1.1 KB) leave the
  29 KB `CLAUDE.md` — about 15 %. Other stacks migrate only after the pilot.

## Non-goals

- Role agents (`.claude/agents/` for enrich, docs, …) — separate issue and brainstorm.
- Converting user-level partials to `~/.claude/rules/`: partials are not file-scoped,
  so a glob-less rule would load every session exactly like the partial does today.
  (Possible later exception: `skill-authoring.md` scoped to `**/SKILL.md`.)
- Pipeline-side injection of only the matching rules into opencode prompts
  (considered as approach B, rejected: depends on plan file lists, misses files
  touched outside the plan).
- `AGENTS.md` generation.

## Design

### 1. Rule source (ai-instructions)

```text
.ai/rules/base/<name>.md       ← installed for every stack
.ai/rules/<stack>/<name>.md    ← installed only for that stack
```

```yaml
---
name: bash-conventions
globs: ["**/*.sh"]
---
<body — moved verbatim from the stack overlay or base>
```

- `name` equals the filename stem.
- `globs` is **required and non-empty**. A rule without a glob would load every
  session — that content belongs in `CLAUDE.md`.
- The overlay/base section the body came from is replaced by a one-line pointer, e.g.
  `Bash conventions — auto-loaded for *.sh (.claude/rules/bash-conventions.md).`
  Humans and agents without rule support still learn the rule exists.

Pilot rules:

| Rule | From | Globs |
|---|---|---|
| `base/powershell-5.1` | base `## Scripting` | `**/*.ps1`, `**/*.psm1` |
| `ci/bash-conventions` | ci `## Bash Conventions` | `**/*.sh` |
| `ci/github-actions` | ci `## GitHub Actions Conventions` | `.github/workflows/**`, `.github/actions/**` |

### 2. Fan-out (`sync-ai-instructions`)

For each rule in `base/` plus the chosen stack's folder, sync writes:

1. `.claude/rules/<name>.md` — `paths:` from `globs`, body, and a
   `<!-- generated by sync-ai-instructions — do not edit -->` marker.
2. `.github/instructions/<name>.instructions.md` — `applyTo: "<globs joined by ,>"`,
   body, same marker.
3. `opencode.json` — merge `".claude/rules/*.md"` into `instructions` (create the file
   if absent; keep all other keys and entries; no duplicate entry on re-run).

Plus:

- **`SKILL.md` appendix:** OpenClaw has no rules mechanism, so sync appends every
  installed rule body to `SKILL.md` under `## Path-scoped rules` (regenerated whole each run).
- **Stale cleanup:** delete generated rule files (marker present) whose source no
  longer exists. Files without the marker are the repo's own and are never touched.
- **Idempotent:** a second run produces an empty diff.
- Existing rule — show a diff before overwriting, matching the skill's current rule
  for `CLAUDE.md`.

### 3. agent-workflow

- **`/integration`, ai-instructions half:** report the number of `.claude/rules/*.md`
  files. (Comparing each rule to upstream would cost one API call per rule; base and
  stack drift already signal a stale sync, so this is left out.)
- **New finding `rules-invisible-to-opencode`:** `.claude/rules/` holds any rule
  (generated or hand-written — opencode misses both) but `opencode.json` is missing
  or no `instructions` entry starts with `.claude/rules/`.
  Graded **broken** on a repo declaring `agent: opencode` (runs proceed without the
  conventions, no error anywhere), **degraded** on a Claude repo (bites only once a
  per-issue `agent:opencode` label is applied) — the same grading pattern as
  `openrouter-not-forwarded`.
- **`agent-workflow-init` / `init-repo`:** no new logic (they already run sync); their
  report lists the rules installed.
- **Pipeline (`agent-implement`):** unchanged — it passes model config via
  `OPENCODE_CONFIG_CONTENT` and writes no `opencode.json`, so the synced file stays.
- agent-workflow is re-synced as the pilot consumer.

## Testing

- **ai-instructions:** extend `build-stacks-drift` CI with a frontmatter check —
  `name` matches filename, `globs` non-empty, no duplicate rule name across `base/`
  and a stack folder.
- **sync (LLM-executed skill, no unit harness):** acceptance run against
  agent-workflow — `CLAUDE.md` shrinks by the three sections, all three outputs exist,
  a second run is an empty diff, a hand-written `.claude/rules/local.md` survives,
  and removing a source rule deletes its generated files.
- **agent-workflow:** fixture tests for `rules-invisible-to-opencode` with mocked `gh`
  output — opencode repo without `opencode.json` (broken), Claude repo without it
  (degraded), repo with correct `instructions` (no finding), repo without rules
  (no finding).
- **Pilot check:** in a Claude session in agent-workflow, `/memory` shows
  `bash-conventions` only after a `.sh` file was read.

## Rollout — issues in landing order

1. **ai-instructions:** `.ai/rules/` format, CI frontmatter check, the three pilot
   rules **as copies** — base and the ci overlay stay untouched.
2. **agent-skills:** sync fan-out, `opencode.json` merge, `SKILL.md` appendix,
   stale cleanup. Released as `sync-ai-instructions` 0.5.0.
3. **ai-instructions:** swap the three source sections for pointer lines.
   **Gate: not before 2 is released** — otherwise every consumer re-syncing in
   between gets pointers to rule files nothing installed, and the base section
   (PowerShell 5.1) disappears from all stacks.
4. **agent-workflow:** `/integration` reporting + `rules-invisible-to-opencode`
   (can land any time), then re-sync as pilot consumer (after 2 and 3).

Between 2 and 3, consumers that re-sync carry the pilot content twice (rule + section)
— harmless, and the window should be short.

## Risks

- **opencode `instructions` globs** — the docs show globs like `.cursor/rules/*.md` in
  `instructions`; confirm a `.claude/rules/*.md` glob resolves relative to the repo
  root in a headless pipeline run before issue 2 merges. Fallback: list each file
  explicitly.
- **Pipeline config merge** — `agent-implement` passes its model config as
  `OPENCODE_CONFIG_CONTENT` (no file written). opencode should merge that with the
  repo's `opencode.json`; plan 2's spike runs the exact pipeline invocation to prove
  the `instructions` entry survives.
- **Frontmatter in opencode:** opencode will see the `paths:` YAML block as text. Harmless,
  but check it does not confuse the model; fallback is a separate frontmatter-free
  copy (rejected for now as duplication).
- **Pilot gain is modest (~15 %)** — the real payoff is the larger stacks
  (dotnet-webapi, flutter, go at ~20 KB). Decide after the pilot whether to migrate them.
